Declare it once

To review · 2026-10-22, revised after the adversarial review (thr_4br4jjycnu) · design only, nothing built

Four records: a unit, an ability, an action, an effect. Actions start deliveries, deliveries carry effects, events trigger actions, and any of them can be code where data can't say it. Of the 31 abilities, 22 become pure data and 8 keep code on purpose. Three abilities that don't exist yet (chain lightning, a meteor that leaves a burning field, an ally/enemy aura) declare without a line of code.

Reply by number. Builds on the units layer (thr_qkq8q3q2gx: every tune number has a unit). Decided: cards keep the written sentences as templates with live numbers, and declarations stay JavaScript.

1. The four records

  1. Effect: one change to one unit, with every parameter a named tune reference, checked against the units layer. 

    { effect: 'slow', magnitude: 'slow', duration: 'duration', stack: 'strongest', scale: null }
// magnitude must be a fraction, duration seconds; a damage amount must be hp

    Types are what statuses and sim already do: damage, heal, shield, modifier (moveSpeed, damageTaken, damageDealt), state (stunned, frozen, prone), displace (knockback, pull), cleanse, and status for a folder's own. slow, haste and freeze are sugar for a modifier or a state. Shorthand is only sugar too: 'slow' expands to the record above, so the meteor's burn, slow and field can each bind their own numbers. scale defaults to level growth for damage and heal.

  2. Action: an effect, or a delivery that carries effects. Every action runs with { source, target, at }: who gets credit, the unit touched, the impact point. A delivery inside a delivery starts from at, so a hit can open an area and a death can explode. Deliveries: shot, area (circle or cone, now), target (one unit, picked), ground (an area that stays, item 6). repeat bounds a delivery that restarts itself; nesting stops at depth 8.

  3. Ability: today's kind stays the input flow (shot, zone, dash, stance, channel, melee, instant), plus an on map from event to actions. The map exists already (statuses.js reactAuras) and fires cast tick amplify damage absorb hit damaged death. It gains the cast lifecycle (release land dashEnd end), passive, every with a seconds reference, and filters ({ source: 'self', target: 'enemyHero' }). A kill is death with source: 'self'. This replaces last draft's tick, end and dot: one map, no timing mini-languages. Statuses take the same map: Slam's bruise is on: { every: 'bruiseEvery', do: [{ effect: 'damage', amount: 'bruiseDamage', periodic: true }] }.

  4. Unit: one definition for heroes, minions, towers, forts, summons and the Warden: { hp, radius, speed, sight, xp, attack?, kit?, traits?, brain? }. A hero is a unit plus selection and presentation (name, order, color, silhouette, icon, draft). Today boss-pull.js hand-builds the Warden's definition; it becomes a declaration with kit: { slot1: 'swing', slot2: 'slam' }, brain: 'boss'. A minion is attack plus brain: 'lane'; Sprinkler's summon is hp: 'hp', radius: 'bodyRadius', lifetime: 'duration', brain: think. MOBA-local; dodgeball keeps its own.

3. Three that don't exist yet

Working names; yours to rename. Numbers live in each tune file, with units.

  1. Ground areas first, since two of the three need them. A ground area has a lifetime, a pulse (every), and separate allies and enemies payloads. Membership rules: an effect with while: 'inside' is keyed to the area that applied it, refreshed each pulse, and lingers linger seconds after exit; on.enter and on.exit fire once per crossing. Overlapping areas follow the effect's stack rule (slows: strongest wins, as decided on 2026-10-14). The area outlives its caster, like summons do, and follow: 'source' turns it into a hero aura. Balloon's puddle, written as a loop in think today, is the first existing user, so ground passes the rule of three with these two.

  2. Rally ring: allies inside run faster, enemies inside are slowed.

    export default {
	name: 'Rally ring',
	kind: 'instant', tell: 'circle', held: 'circle',
	on: { release: [{ deliver: 'ground', at: 'aim', radius: 'radius', lifetime: 'duration', every: 'pulse',
		allies:  [{ effect: 'haste', magnitude: 'haste', while: 'inside', linger: 'linger', stack: 'strongest' }],
		enemies: [{ effect: 'slow',  magnitude: 'slow',  while: 'inside', linger: 'linger', stack: 'strongest' }],
	}] },
	card: 'Chalk a {radius} ring for {duration}. Allies inside run {haste} faster; enemies inside are slowed by {slow}.',
}
// tune: radius 3.5 m · duration 5 s · pulse 0.25 s · haste 0.25 · slow 0.3 · linger 0.5 s · cooldown 14 s

  3. Meteor: a delayed circle that leaves a burning field.

    export default {
	name: 'Meteor',
	kind: 'zone', tell: 'circle', held: 'circle',                // delay and radius from tune, as Rain
	on: { land: [
		{ effect: 'damage', amount: 'damage', targets: 'enemies' },
		{ deliver: 'ground', radius: 'fieldRadius', lifetime: 'fieldLife', every: 'burnEvery',
			enemies: [
				{ effect: 'damage', amount: 'burnDamage', periodic: true },
				{ effect: 'slow', magnitude: 'fieldSlow', while: 'inside', linger: 'burnEvery' },
			] },
	] },
	card: 'After {delay}, {damage} in {radius}. The crater burns for {fieldLife}: {burnDamage} every {burnEvery} and slowed by {fieldSlow}.',
}

  4. Chain lightning: zap one enemy, then jump. No new delivery; a target that re-targets from its own impact, bounded by repeat. 

    export default {
	name: 'Chain lightning',
	kind: 'instant', tell: 'tether', held: 'circle',
	on: { release: [{ deliver: 'target', pick: 'nearestAim', targets: 'enemy', range: 'range',
		hit: [{ effect: 'damage', amount: 'damage', scale: { level: true, perRepeat: 'falloff' } }],
		then: { from: 'at', pick: 'nearestUnhit', range: 'jumpRange', repeat: 'jumps' },
	}] },
	card: 'Zap the enemy nearest your aim for {damage}, then up to {jumps} more within {jumpRange}, each {falloff} weaker.',
}

    nearestUnhit picks by distance, ties by id; a dead target still hands on its at, so a kill doesn't end the chain.

4. Execution rules

  1. Hook stages. Every event has before, replace and after. before returning true consumes the event, as onHit does today (combat.js:239: Pass heals an ally instead of hitting). replace runs instead of the declared actions; after runs once they're done. Today's hooks map onto these unchanged.
  2. Lethal damage. One target's effects resolve as one hit, as sim.hit does now: statuses, then damage. After a lethal hit, further effects aimed at that target are dropped; actions aimed elsewhere (the next jump, a death explosion, a heal on the caster) still run, and after sees lethal: true.
  3. Determinism. Each declared loop keeps the order and evaluation point of the code it replaces. Areas iterate the population order of targeting.js (summons, heroes, dummies, minions, structures), never re-sorted. Projectile damage is snapshotted at launch (casting.js:244), area damage at release, zone damage at landing, status numbers when applied. No universal "read at hit time" rule: that would change damage after a mid-flight level-up. New deliveries document their own order (chain: distance, then id).
  4. Network and replay. Generated status keys equal today's (tangle.slow, ward.shield, redLight.freeze), and facts keep their shapes. Equal shapes don't prove equivalence, so every migration slice proves itself the hard way: same seeds, byte-identical match logs against the base revision.
  5. Boundaries. The vocabulary lives in src/modes/moba/; core gets only the units layer. Dodgeball's characterization snapshots stay identical, checked once per slice.

5. Inferred, and where it stops

  1. Inferred: statuses from effect records, under today's keys; the area, target and ground loops; card templates and rows with units; bot tactics from delivery and payload (an ally target with heal or shield gets a save tactic; Mender bots never heal today); kit sheet (bun run kit, one line per ability).
  2. Checked: every declared reference exists in tune and has the unit its field needs; template tokens resolve; unknown fields fail. Unused tune keys are an advisory list, never a failing check: hooks read tune however they like.
  3. Rule of three. A verb or delivery joins when a third ability needs it. The three new abilities add none: haste is a modifier, chain is a repeated target, ground has Balloon's puddle. A slice that wants more than two new words stops and rethinks.
  4. Code on purpose, eight folders: Flying kick's first-body dash, Slide's puddle reach, Swap's blink to the ricochet, Cushion's wall, Stagger's damage bank, Tag out's position swap, Balloon's flight and pop, Sprinkler's sweeping jet. Red light keeps a one-line where filter (only targets moving faster than movingSpeed).

6. Migration, in slices

Each fits ~40 tool calls; each ends with byte-identical logs against the base revision.

  1. Effect records for statuses only. Pass, Rain and Tangle's three identical slow blocks, Ward's shield and Red light's freeze come from records with the same keys; status fields accept tune names; the reference check joins bun run check. No loops change.
  2. Cards and kit sheet: templates through the units layer, trait cards, bun run kit. View only. Waits for the units thread.
  3. Area and the on actions: Tangle, Around the world, Red light, plus hook stages.
  4. One unit definition: the Warden declared, heroes as unit plus presentation, summons with tune names.
  5. Target: Mend, Ward, Tag out, Pass's ally heal as a before; then the save tactic as its own commit, judged by simulate --base, since it's meant to change behaviour.
  6. Ground: Balloon's puddle, enter and exit, overlap rules; then one of the three new abilities built for real, as the creative proof.
