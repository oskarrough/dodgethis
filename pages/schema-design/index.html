Declare it once

To review · 2026-10-22 · design only, nothing built

Half the work is done already. Since the ability-system slices, an ability is a data head (kind, statuses, tell, effects) and a code body (hooks). 12 of the 31 abilities have no body at all. Many of the other 19 hand-write the same three loops: hit everyone in an area, pick the ally nearest the aim, declare a slow. Name those loops, and 22 are pure data, Red light needs a one-line filter, and 8 keep code: the odd ones worth keeping.

Reply by number. Builds on the units layer that thread thr_qkq8q3q2gx is adding (every tune number gets a unit: s, m, fraction, hp…). Line counts are the working copy on 2026-10-22.

1. The shapes

Two halves. Delivery is today's kind, plus two new ones: area and target. Payload is new: a hit list of verbs, applied to every unit the delivery touches. Each verb reads stats by their usual tune names, so the declaration carries no numbers:

Verb Reads from tune Today, hand-written in
damage damage (level growth by the engine) Tangle, Around the world
heal healAmount, critChance, critMultiplier Mend, Pass
shield shield, duration Ward, Swig
slow slow, duration Pass, Rain, Tangle (three identical status blocks)
freeze duration Red light
knockback, pull knockback, time / dragDistance, dragTime Around the world, Throw
cleanse a list of tags Tag out

A different key is { slow: 'soakSlow' }. A folder's own status is named by key: hit: ['bruise']. Status fields take a stat name too: duration: 'duration' instead of ({ stats }) => stats.duration.

  1. Area: a burst from you or your aim, a circle or a cone. Tangle, 75 lines today: a slow status block, then a 45-line onRelease that loops enemies, checks the cone and cover, scales damage by level, calls sim.hit, and presents the impact. After, 12: 

    export default {
	name: 'Tangle',
	kind: 'area', from: 'self', shape: 'cone',   // range, angle from tune
	targets: 'enemies', blockedBy: 'cover',
	hit: ['damage', 'slow'],
	tell: 'cone', held: 'cone',
	effects: { cast: true, impact: true, pose: 'tangle' },
	card: 'A {angle} cone deals {damage} and slows by {slow} for {duration}. Follow Throw with this.',
}

    Around the world is the same with shape: 'circle', targets: 'enemyHeroes', hit: ['damage', 'knockback']: 56 lines to 10.

  2. Target: one unit near your aim, within range. Ward, 43 lines today: a shield status, Mender's shared target picker, an onRelease that applies it and presents a contact. After: 

    export default {
	name: 'Ward',
	kind: 'target', targets: 'ally', pick: 'nearestAim',
	hit: ['shield'],
	tell: 'circle', held: 'circle',
	effects: { cast: true, impact: true, pose: 'menderWard' },
	card: 'Shield the ally nearest your aim within {range} for {shield} for {duration}.',
}

    Mend is hit: ['heal']. Tag out is hit: ['cleanse'] plus its swap, which stays a hook.

  3. Shot (exists): gains hit. Throw's projectileStats and 10-line onHit become hit: ['damage', 'pull']. Pass splits by side: hit: { allies: ['heal'], enemies: ['damage', 'slow'] }, and its 20-line onHit and slow block go.

  4. Timing: tick runs each tick of a channel or stance, end after a dash or stance ends. Swig today sets hero.cd[2] by hand every tick, so moved to another slot it would start the wrong cooldown. After: 

    export default {
	kind: 'channel', root: true, cancelOnMove: true, cancelOnCast: true,
	tick: [{ shield: 'shieldPerSecond', grow: true, life: 'shieldLife' }],
	cooldownFrom: 'end',
	effects: { cast: true, pose: 'swig' },
	card: 'Root and drink, gaining shield. Orders, casts and disables interrupt the drink.',
}

    Dive becomes kind: 'dash', catch: { until: 'prone' }, end: ['prone']; Catch declares the same catch and loses its onStart.

  5. Status (exists): gains dot. Slam's bruise hand-builds a 10-field sim.hit every second. After: bruise: { label: 'Bruise', tags: ['debuff'], stack: 'refresh', dot: 'bruiseDamage', every: 'bruiseEvery', duration: 'bruiseDuration' }.

  6. Aura: a payload applied every tick to units inside a radius around a hero or summon, refreshed while they stay. Nothing calls itself an aura yet, but Balloon's puddle is one, written as a loop in think. After: aura: { phase: 'puddle', radius: 'radius', targets: 'enemies', hit: ['soak'] }. The flight and pop stay code.

  7. Unit: minions, towers, forts and summons share one shape: { hp, radius, speed, attack: { damage, rate, range, tell }, xp, brain }. The tune already holds them flat (tune.tower, tune.minions.ranged); what changes is that the shape gets a name. Sprinkler's summon goes from hp: (stats) => stats.hp, radius: (stats) => stats.bodyRadius, lifetime: (stats) => stats.duration to hp: 'hp', radius: 'bodyRadius', lifetime: 'duration', with think as its brain.

  8. Hero (exists): { name, basic, kit, silhouette, icon } is already a declaration. Only the trait card moves to a template. Mitts's trait: () => ({ … summary: `Hold a caught shot for ${n(tune.catching.pocketLife)} s…` }) becomes trait: { name: 'Pocket', summary: 'Hold a caught shot for {catching.pocketLife}, then send it back with Toss.' }.

2. What gets inferred

  1. Statuses. The seven hand-declared slow, shield and freeze blocks (Pass, Rain, Tangle, Ward, Red light, Swig, Balloon's soak) come from the verbs, under today's keys (tangle.slow, ward.shield).
  2. Sim. The engine owns the area and target loops, damage growth, impact and contact facts, and slot ids. That kills the hard-coded slot: 'slot2' in Tag out, Swig's cd[2] and the growth formula copied into two folders.
  3. Cards. {damage} in a template prints the live number with its unit ("110", "1.5 s", "40%"), so a card can't drift from the tune. Rows come from the verbs (slow: "40% for 1.5 s"), replacing the fixed row table in tooltip.js.
  4. Bots. Tactics come from shape and payload: an enemy circle is radial, a cone is cone, an ally target with heal or shield gets a new save tactic. Four folders hand-write "hurt ally within range, lowest HP first" (Pass, Balloon, Sprinkler, Tag out), and Mender's Mend and Ward are bot: false, so Mender bots never heal.
  5. Desk. Sliders group by verb ("Slow: 40%, 1.5 s") with instruments from the units layer. A tune key that no verb, template or hook reads gets flagged as dead.
  6. Check. bun run check validates every declaration: a verb's stat keys exist, template tokens resolve, each kind has its required keys (an area needs radius, or range and angle), unknown fields fail. A typo is a red check instead of a silent NaN.
  7. Kit sheet. bun run kit prints one line per ability: "Tangle · Hook W · cone 90° 3.5 m · 110 dmg · slow 40% 1.5 s · cd 6 s". Balance talk and agents read 31 lines instead of 31 folders.

3. Where it stops

  1. Hooks stay. Every hook (onStart, onRelease, onHit, watch…) still runs, after the declared payload. A where(target) filter covers the one-line oddity: Red light only freezes targets moving faster than movingSpeed. Status functions are still accepted when a stat name can't say it.
  2. Rule of three. A verb joins the vocabulary when a third ability needs it. Until then it's a hook. If a slice wants more than two new verbs, stop and rethink: a schema that grows a flag per ability is a worse JavaScript.
  3. Code on purpose, eight folders: Flying kick's first-body dash, Slide's puddle reach, Swap's blink to the ricochet, Cushion's wall, Stagger's damage bank, Tag out's position swap, Balloon's flight and pop, Sprinkler's sweeping jet. Plus the engines they lean on (ricochet bounces, catch and pocket) and hero trait hooks (Fletcher's momentum, Mitts's death reset).

4. Migration, in slices

Each slice fits ~40 tool calls and has one proof: the same seeds give byte-identical match logs against the base revision. A diff is a bug, not balance.

  1. Area and the first verbs (damage, slow, freeze, knockback, generated statuses): Tangle, Around the world, Red light. Pays off soonest: the most copied loop, about 130 lines out, and every later slice reuses the verbs.
  2. Cards, check and kit sheet: templates through the units layer, trait cards, the declaration check, bun run kit. View and tooling only, no sim risk. Waits for the units thread to land.
  3. Target: Mend, Ward, Tag out; heal, shield, cleanse. Then the inferred save tactic as its own commit, judged by simulate --base, because that one is meant to change behaviour.
  4. Shots and timing: Throw (pull), Pass (split by side), Dive and Catch (catch), Swig (tick, cooldownFrom), Slam's bruise (dot).
  5. Units and auras: one shape for minions, towers, forts and summons; their cards read it; Balloon's puddle becomes the first aura.

5. Risks

  1. Determinism. Engine loops iterate in id order, as the hand-written ones mostly do, and keep today's float expressions exactly (damage growth is damage * (1 + growth * (level - 1)); reordering it changes rounding). Verbs read stats at hit time, never cached at load, or desk sliders stop working mid-match.
  2. Network and replay. Generated status keys equal today's, and facts keep their shapes (impact, contact), so peers and saved logs read the same. Peers already run one build, and validFact still checks every fact.
  3. Dodgeball. Everything lives in src/plugins/moba/. The characterization snapshots must stay identical; run them once per slice.
  4. Plugin boundaries. The vocabulary is moba's (next to ability.js); core gets only the units layer. Mechanics like the boss's Slam use the same verbs through moba. tests/boundaries.test.js holds the line.

6. For Oskar

  1. Card voice. Templates keep your sentences with live numbers ("…moving faster than {movingSpeed}… Standing still is safe."), or cards write themselves from the verbs ("Freezes moving enemy heroes within 4 m for 1 s")? My pick: templates. The flavour line is the good part.
  2. How data? Declarations stay JavaScript (stat names where they can, functions allowed), or become strict JSON so an ability could one day come from an in-game editor or a shared mod, with every hook in a named file beside it? My pick: JavaScript now, shaped so it's JSON-clean apart from the hooks, and decide when someone wants to share one.
