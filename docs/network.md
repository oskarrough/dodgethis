# Configure online connections

DodgeThis uses pinned PeerJS 1.5.4, loaded in [index.html](../index.html), with private lobby codes and a host-to-guests connection pattern adapted from Doodle District. [net.js](../src/plugins/online/net.js) owns the handshake, version checks, timeouts, and connection cleanup.

The defaults use PeerJS's public signaling service, Google/Cloudflare STUN, and the reference's public OpenRelay TURN configuration. Signaling connects peers; STUN discovers direct routes; TURN relays traffic when direct routes fail. These third-party services can be blocked, rate-limited, or unavailable. The public relay is for best-effort use and carries no production reliability guarantee.

Set `window.DODGETHIS_PEER_OPTIONS` before the main module runs to replace the full PeerJS options object. For example, place a deployment-specific script before `/src/main.js`:

```html
<script>
	window.DODGETHIS_PEER_OPTIONS = {
		debug: 0,
		// Omit these four fields to keep the public PeerJS signaling service.
		host: 'signal.example.com',
		port: 443,
		path: '/peerjs',
		secure: true,
		config: {
			iceServers: [
				{ urls: 'stun:stun.example.com:3478' },
				{
					urls: ['turns:turn.example.com:443?transport=tcp'],
					username: 'deployment-issued-username',
					credential: 'deployment-issued-short-lived-credential',
				},
			],
		},
	}
</script>
```

Use a relay you operate or a provider you can monitor for production. TURN credentials delivered to browsers are visible to players; issue short-lived credentials through your deployment rather than embedding long-lived account secrets. Every player must use compatible signaling configuration and the same game protocol version. PeerJS's [official setup guide](https://peerjs.com/client/getting-started) and [API reference](https://peerjs.com/client/api/peer) describe server and ICE options.

# Simulation ownership

[online-session.js](../src/plugins/online/online-session.js) owns the lobby roster and host settings. Rooms carry the host's mode id, refreshed from the current mode at Start. A mode can declare its human capacity; pending joins reserve space against it and Start checks it again. MOBA declares six. If a guest cannot start it, it leaves with a notice and returns to its previous solo screen. When the host starts, every browser starts that mode (not its own previously active one) with the lobby's roster under a shared session: the host's is authoritative, a guest's is not, and neither may pause, restart or cheat. The host runs the ordinary dodgeball flow and calculates charge strength, movement, combat, pickups, bot actions, round endings and scores. A guest builds no bodies or bot brains; it interpolates what it is sent through [replica.js](../src/plugins/dodgeball/replica.js) and the core's snapshot buffer. Nothing depends on matching physics seeds. The MOBA lobby now accepts the same shared session and roster: every human gets a body on a separate spawn mark. Its guest keeps those bodies in an unstepped sim; [lobby-replica.js](../src/plugins/moba/lobby-replica.js) validates the complete population and buffers hero/dummy poses, shots, zones and combat/HUD state by 100 ms. Its bounded fact queue discards stale cues after a hidden-tab stall. Ready seats, host-resolved picks and claims replicate too. The hello acknowledgement carries shallow mode-owned join data, validated by the host mode before seating the peer; the roster keeps that data alongside the transport-owned participant id. MOBA carries the saved hero pick here so both sims seed the same first frame. Once every human holds a full box, the host starts loading with the claimed teams and heroes and fills vacant seats with host-only bots. Loading and early lane snapshots retain that handoff for the grace period in MOBA's tune, then stop sending it. The guest keeps its own edge-pan preference. A session or run replacement cancels the descent without reparenting the replacement's canvas. [lane-replica.js](../src/plugins/moba/lane-replica.js) shares the lobby's buffered combat poses and cue timing for minions, structures and rubble, Ball, globes, team XP and match timers. Its snapshot recap ledger retains deaths, damage and XP even when stale presentation cues are discarded. The lane's wire projection drops host-only bookkeeping, rounds floats and packs repeated entity and recap fields into rows; the replica expands them before validation. HP and max HP remain explicit. Full sim snapshots used by traces are unchanged.

[link.js](../src/plugins/online/link.js) is the wire, and it knows nothing about either game. It reads the current mode contract for every envelope, allowing lobby-to-lane replacement without resetting the room, intent sequence or envelope sequence. Pending old-run facts are dropped when the contract changes. A guest sends its intent frames (`{ matchId, seq, frame }`): edges (including point orders) at once, a changed frame at most every 14 ms, an unchanged one every 100 ms as a keepalive. Protocol 4 requires the host mode id in the lobby/start contract and retains raw string serialization. Before `JSON.parse`, every guest message (including malformed, stale and unknown messages) spends one token from its seat's bucket (refilled at 120/s, holding up to 360 for stalled-tab backlogs) and must fit 2048 UTF-8 bytes. The host accepts intents only from the peer that owns that seat, in sequence, copied through core `readIntent` (known fields only, or null), then feeds the owned frame to the seat. Three dirty one-second windows out of the last five remove the peer; pauses and good packets do not erase recent abuse. Both sides display the removal notice, adding “Match cancelled” only if a match was running. The host waits for the guest to close after reading the refusal, with a one-second cleanup fallback. Rate, cap and windows live in online's `tune.input`. A seat silent for half a second stands still and drops its charge. The host sends `{ matchId, epoch, seq, state, facts }` envelopes: `state` is the mode's `snapshot()`, and `facts` are the gameplay facts not yet sent to that guest, numbered so it presents each once. Each guest has an independent fact cursor. If its channel's `bufferedAmount` exceeds two candidate envelopes, the link skips its state without advancing that cursor; pending facts ride its next successful sends, in bounded batches. Other guests keep receiving state. A run replacement drops the old run's pending cues for every guest. A guest accepts envelopes only if they are newer and their facts pass the mode's `validFact`. It presents those facts once even if the mode's `apply` rejects the state; `game.link.stats.rejected` and `rejectionReason` diagnose rejected snapshots. Well-formed host envelopes refresh the liveness clock, so a rejected state is not reported as a lost host. Ten seconds without a well-formed envelope ends the session. The protocol version is 4. Older JSON-serialized connections receive object refusals; protocol-2 objects coerced into a new tab's raw channel produce a readable version-mismatch notice. Mixed versions cannot join.

Envelopes target 20 Hz with approximately 80 ms guest interpolation. A human-only envelope is about 3 KB (2.9 KB measured on 2026-09-28) and two humans plus two bots about 4.2 KB: approximately 60 KB/s and 84 KB/s per guest when the host reaches the target rate, before transport overhead. `game.link.stats` counts envelopes and UTF-8 bytes including the transport wrapper, and exposes `envelopeP95` (bytes over the last 6000 envelopes), `envelopeSamples`, and host `skipped` counts. Queue thresholds, sample count and fact batch size live in online's `tune.link`. The frame-driven sender sends less often when host rendering falls below 20 FPS. These are initial local measurements, not WAN latency guarantees. Full movement prediction, mesh links, and host migration are outside this implementation.

# Join by link

A room's link is its code as the path: `dodgethis.0sk.ar/ABCDE`. The Worker serves the game page for that path (Vite's dev server already does), and `main.js` skips the splash into solo practice in the lobby while online joins the room on the first frame. A dead or refused code stays in solo practice with a notice and drops the code from the address, so a refresh doesn't retry it. The room panel's Copy link copies it, falling back to a selected field on plain-http LAN play.

A room in the lobby reseats everyone, as before. Mid-lane, the host keeps accepting while a bot holds a seat: the mode's `seatLate` gives the joiner the bot's seat on the side with fewer humans, hero, spot and HP as they stand, and the sim drops only that bot's brain. The joiner's participant id is the seat's (`bot-B-0`, say), no longer its peer id; the room roster maps each peer to its seat, and the link feeds each peer's frames to that seat. For the next few seconds (MOBA's `handoffFor`) lane snapshots carry the seating (roster and setup), and a late guest, which starts waiting for it rather than building a lane, builds the running lane from it and lands in its seat with no descent. A human who leaves mid-lane hands the hero back to a bot and reopens the seat. A guest sends a keepalive once a second even from a hidden tab; a peer silent for `SEAT_TIMEOUT` (10 s), such as a killed tab, is let go.

Keep the host page running: browser suspension or loss of its connection ends the session after a timeout. In-game developer cheats, round editing and pause are disabled online; Escape opens the online menu, where anyone can resume or leave and the host can return everyone to the lobby.
